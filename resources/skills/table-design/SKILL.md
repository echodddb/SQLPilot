# 建表与索引设计

## 什么时候用
用户要建新表、加字段、问「这个表怎么建」「索引加在哪几列」。

## 建表规范（先按这套给方案，用户的规范优先）
1. **主键**：必须有。单列自增/序列（`BIGINT`）或业务无关的代理键；不要用业务字段（手机号、订单号）当主键。
2. **字段类型**：
   - 整数够用就用最小类型（`TINYINT` / `INT` / `BIGINT`），但主键和外键统一 `BIGINT`
   - 金额一律 `DECIMAL(18,2)` 或更宽，**禁用 `FLOAT/DOUBLE`**
   - 时间用 `DATETIME(3)`（MySQL）/ `TIMESTAMP` 或 `DATE`（Oracle），不要用字符串存时间
   - 布尔用 `TINYINT(1)`（MySQL）/ `NUMBER(1)`（Oracle）
   - 变长文本用 `VARCHAR`，超长正文才用 `TEXT`/`CLOB`（后者不能建普通索引）
3. **可空性**：除业务上确实可空外，一律 `NOT NULL DEFAULT`；`NULL` 会让索引统计和 `NOT IN` 出问题。
4. **字符集**：MySQL 统一 `utf8mb4` + `utf8mb4_0900_ai_ci`（8.0）/ `utf8mb4_general_ci`（5.7），不要混用。
5. **注释**：表和每个字段都要有 `COMMENT`，这不是可选项——后面接手的人只能靠它。

## 索引设计
- **联合索引顺序**：等值条件列在前，范围条件列在后；`ORDER BY` 的列尽量接在最后，避免额外排序。
- **选择性**：`COUNT(DISTINCT col)/COUNT(*)` 低于 1% 的列单独建索引意义不大，适合放在联合索引尾部。
- **覆盖索引**：查询只用到少数列时，把这几个列放索引尾部，能免掉回表。
- **不要**：给每个外键都建索引是必要的，但给每个字段都建索引会让写入变慢、优化器选择变差。
- **前缀索引**：长 `VARCHAR`（如 URL、备注）用 `INDEX(col(20))`，先算 `COUNT(DISTINCT LEFT(col,20))/COUNT(*)` 看区分度够不够。

## 输出格式
```
表：<schema>.<table>（用途一句话）
DDL：<完整 CREATE TABLE，含 COMMENT>
索引：<每个索引 + 为什么这么排>
容量预估：按每行约 N 字节、预估 M 行 → 约 X GB（含索引）
注意：<字符集/时区/分区等需要确认的点>
```
DDL 用代码块给出，让用户能直接复制；不要在方案阶段就执行。

## 红线
- 不给出没有主键的表设计。
- 不建 `TEXT/CLOB` 上的普通索引（MySQL 需要前缀长度，Oracle 需要 `CTXSYS` 或函数索引），要建就说明限制。
- 分区不是性能银弹：单表 < 5000 万行或没有明显时间维度的，不主动建议分区。
- 具体类型/长度以实际业务量级为准，拿不准时给出两个档位（如 `VARCHAR(64)` / `VARCHAR(255)`）并说明取舍。
