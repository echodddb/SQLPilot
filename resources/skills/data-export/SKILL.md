# 数据导出与脱敏

## 什么时候用
用户要把查询结果导出、给测试环境造数据、或把数据发给外部（乙方/审计/同事）。

## 流程
1. **确认口径**：导出哪张表/哪条 SQL、时间范围、是否需要去重。口径不清就先问，不要自己扩大范围。
2. **先数行数**：同条件 `SELECT COUNT(*)`。超过 10 万行时提示用户「将分批或加条件」，不要直接全量拉。
3. **定脱敏规则**（发给外部时必做）：

| 字段类型 | 处理方式 |
|---|---|
| 姓名 | 保留姓，名替换为 `*`（`张*`） |
| 手机号 | 保留前 3 后 4（`138****1234`） |
| 身份证 | 保留前 6 后 4，中间 `*` |
| 银行卡 | 只保留后 4 位 |
| 邮箱 | 用户名首字符 + `***` + 域名（`z***@corp.com`） |
| 地址 | 保留到区/县，门牌号去掉 |
| 密码/密钥 | 直接剔除，不要脱敏后保留 |

4. **导出**：SQLPilot 的查询结果在右侧「产物」面板里，可以直接「导出 CSV」（带 BOM，Excel 打开不乱码），也可以「复制」后粘到 Excel。
5. **交付说明**：报告导出行数、是否截断、脱敏了哪些字段。

## 脱敏 SQL 写法
- MySQL：`CONCAT(LEFT(name,1),'*')`、`CONCAT(LEFT(phone,3),'****',RIGHT(phone,4))`
- Oracle：`SUBSTR(name,1,1)||'*'`、`SUBSTR(phone,1,3)||'****'||SUBSTR(phone,-4)`
- 空值要先判断：`CASE WHEN phone IS NULL THEN NULL ELSE … END`，否则整列变空字符串。

## 红线
- 导出的数据里有身份证、手机号、密码等敏感字段且用途是「给外部」时，**必须先脱敏再导出**，并在回复里说明做了什么处理。
- 不要把敏感字段拼进 URL、文件名、日志（会外泄）。
- 不要为了让结果好看而 `LIMIT` 掉数据却不说明——行数必须如实报告。
